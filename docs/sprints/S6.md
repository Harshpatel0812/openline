# Sprint 6 review — Pipeline and Pipeline Reality Check

Goal: one board for the whole team's pipeline, and an honest answer to "is this deal really at
this stage?". Met: **yes**. Spec: `docs/product/OL-E7-pipeline-and-reality-check.md`.

## Shipped

- **Stages:** one pipeline per workspace with the default stages (Discovery 10 % → Won / Lost),
  each with a probability, a stale limit and up to five entry criteria tied to evidence types.
  Owners and admins edit them in Settings → Pipeline; a stage with deals can't be removed.
- **Deals:** company, contacts, owner, amount (whole cents, never floats) and currency, close date,
  next step. Create one from the Deals page, a contact, a company or an inbox reply (prefilled).
  Every move is recorded in the stage history and the audit log. Reps see every deal and change
  their own; managers change all.
- **Board and list:** a column per stage with count, total and weighted total, drag and drop (and a
  keyboard "Move to…" menu), filters (owner, close dates, stale, flagged), a list view and a
  forecast strip (open, weighted, this month, this quarter). Stale and overdue deals show on the
  board and under "Deals needing attention" on Today.
- **Pipeline Reality Check:** Scout reads the deal's emails and looks for evidence (decision maker,
  budget, need, timeline, proposal, verbal yes). Every yes or no needs the email's exact words;
  Openline's own code then compares it with the stages' entry criteria and flags, for example,
  "Stage says Proposal, evidence says Discovery". Date and stale checks run without the AI. The
  "Move to <stage>" suggestion moves nothing until the owner or a manager accepts it. "Check now"
  (10 a deal a day) and a daily run for deals with new activity, within a quarter of the
  workspace's Scout credits.

What the review fixes changed, in short:

- Many "Check now" clicks or scheduled runs at the same moment can no longer go past the daily
  limit or the Scout budget: each run is recorded, with its largest possible cost set aside, before
  the AI is asked. There is also an hourly limit per person.
- A rep no longer sees the subject of emails in a teammate's mailbox on a deal's timeline (see
  decision 1). An email can't raise a flag unless the AI quotes it word for word.
- Linking a task to a deal needs the right to edit that deal, and the database itself now refuses
  links between workspaces (deal → company, contact; task → deal).
- "Not right" on a date or stale flag now takes it off the board's count and the Flagged filter
  too; a run without the AI (Scout off, budget, AI error) no longer clears the AI's flags or
  suggestion; a suggestion that no longer applies is closed and the panel refreshes.
- Deleting a contact removes the quotes taken from their emails from stored checks.
- Stale is measured in exact 24-hour days, so daylight-saving changes don't move the line.

## Not shipped / later

- Accuracy of Reality Check on a real model: `pnpm --filter @openline/ai eval:reality` once an AI
  provider is set up (target 80 % agreement with a sales manager). The test set was written by us,
  so treat its scores with care.
- Multiple pipelines, products and quotes, forecast targets, win/loss analysis (v2).
- Reassigning a removed member's deals is manual (a manager edits the owner).
- The hourly "Check now" limit is kept in memory per API instance; it moves to Redis with the
  other limits when we run more than one instance.
