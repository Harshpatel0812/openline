# Sprint 3 review — Sending engine (built Nov 14, 2026)

Goal: a verified user connects a mailbox and sends a multi-step sequence that obeys business hours,
caps, suppression, consent and unsubscribe law — with nothing able to send twice or to the wrong
person. Met: **yes**.

## Shipped

- **Account email:** verification (required before connecting a mailbox, activating or enrolling),
  forgot / reset password (resets end every session), resend with rate limits. Openline's own mail
  goes through SMTP (Mailpit locally) and never blocks a request.
- **Workspace settings:** CAN-SPAM postal address (sending waits until it exists), default time
  zone.
- **Mailboxes:** SMTP (any provider; login checked before saving; credentials sealed with
  AES-256-GCM per workspace) and Gmail (send-only scope, signed OAuth state). Daily cap, health
  status, pause / resume / remove.
- **Sequences:** steps with delays, `{{variable|fallback}}` personalisation, threading as a reply,
  per-sequence send window, preview, activate / pause / archive, stats.
- **Enrollments:** bulk enroll with reasons for every skip (already enrolled, suppressed, no
  consent, unsubscribed, bounced), pause / resume / stop / mark replied, per-contact history.
- **Sending engine (ADR 0004):** Postgres queue, no Redis. Before every send: suppression,
  unsubscribed / bounced, CASL and GDPR consent, postal address, mailbox health, the contact's
  local business hours (DST and :30/:45 zones), rolling 24-hour cap, 60–300 s random spacing. Hard
  bounces mark the contact; >3 % bounces pause the mailbox; temporary errors back off 5 → 80 min.
- **Unsubscribe:** RFC 8058 one-click header (Gmail / Yahoo bulk-sender rules) plus a footer link
  to a page that masks the address; both suppress the contact and stop every enrollment.
- **Consent records:** basis, source, date; implied consent expires on CASL's 24 / 6-month clocks.
- **Web app:** verify / forgot / reset pages, workspace and mailbox settings, sequences (list,
  builder, preview, enrollments), enroll dialog, consent and sequence cards on contacts, "Today".

### What the reviews caught (and the fix)

- **Staging could email real prospects** (one image with `NODE_ENV=production` is promoted from
  staging): deployments now declare `APP_ENV`; only `production` sends for real by default;
  staging needs its own catch-all inbox for sandbox outreach.
- **The queue would have claimed nothing in production** (RLS hid rows from the non-superuser
  function owner; tests ran as superuser): the claim function now belongs to a dedicated
  `openline_scheduler` role, and the isolation test runs it the production way.
- **DNS rebinding around the SMTP host check:** the host is resolved and checked on every send and
  the connection goes to that exact address (certificate still checked against the name).
- **Pause / stop / "replied" during a send was overwritten**, and **a slow send could be sent twice
  by a second worker**: send reservations (unique per step) plus "a person's change wins" updates.
- **One failing row stopped the whole batch:** rows are isolated; a send that can't be recorded is
  never re-sent and is flagged for a person.
- Removed teammates' mailboxes kept sending; reps could resume enrollments on others' mailboxes;
  withdrawn consent looked valid; verification email echoed the sign-up name to unverified
  addresses; small timing difference on forgot-password; :30/:45 time zones opened late.

- Microsoft 365 mailboxes → Sprint 4.

- Open / click tracking (off by design for deliverability until custom tracking domains exist).
